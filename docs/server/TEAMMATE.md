# 팀원에게 부탁할 것 (Supabase)

ShortsAI(v0.11.x)가 팀원 Supabase 프로젝트(`zpmkgmqqdrtuefqejtbm`)에 사용 기록을 올리도록 만들었다. 팀원 hanbakja `focusai` 브랜치의 업로드 설계(동의 창, 설치 번호, 공개 키로 넣기만, 같은 id는 한 번만, 서버에서 지우기)를 그대로 이어받았다.

## 1. 팀원에게 보낼 메시지 (그대로 복사)

> 우리 앱(ShortsAI)이 네 Supabase에 사용 기록을 올리게 만들었어. 네가 만든 sessions, interventions, lock_attempts 표와 함수는 **하나도 안 바꾸고** 그대로 써.
> 예측 모델 기록, 하루 목표, 다른 사용자 비교, 처음 설치할 때 유형 찾기에 쓸 **새 표·함수를 더하는 SQL 파일**이 하나 있어. 이름이 전부 `sai_`로 시작해서 네 것과 안 겹쳐.
> Supabase 대시보드 → **SQL Editor** → New query에 `shortsai_v1.sql` 내용을 붙여 넣고 **Run** 한 번만 눌러 줘. 여러 번 눌러도 괜찮아.
> 문제 생기면 `shortsai_v1_rollback.sql`을 같은 곳에서 Run 하면 우리가 더한 것만 지워지고 네 표와 기록은 그대로야.
> 실행하고 나서 Table Editor에 `sai_`로 시작하는 표 6개가 보이면 성공이야.

같이 보낼 파일 (저장소 `supabase/` 폴더):
- `shortsai_v1.sql` — 더하는 SQL
- `shortsai_v1_rollback.sql` — 되돌리기 SQL

## 2. 팀원이 하는 일

| 순서 | 할 일 | 시간 |
|---|---|---|
| 1 | Supabase 대시보드 로그인 → 프로젝트 → 왼쪽 **SQL Editor** | 1분 |
| 2 | **New query** → `shortsai_v1.sql` 전체 붙여 넣기 → **Run** | 2분 |
| 3 | 왼쪽 **Table Editor**에서 `sai_clusters`, `sai_compare_demo`, `sai_daily`, `sai_intervention_details`, `sai_opens`, `sai_session_links` 6개가 보이는지 확인 | 1분 |

프로젝트가 일시 정지(7일 동안 활동 없음) 상태면 먼저 **Restore**를 눌러 켠다.

## 3. 나중에 필요할 수 있는 것 (지금은 아님)

| 무엇 | 언제 | 왜 |
|---|---|---|
| 프로젝트에 나를 멤버로 초대 | 데이터를 직접 보고 싶을 때 | 대시보드는 멤버만 볼 수 있다 |
| DB 연결 정보 (Settings → Database → Connection string, 풀러 주소) | 주 1회 학습 자동화, Spring Boot 서버를 붙일 때 | 전체 기록을 읽으려면 필요. 비밀번호가 들어 있으니 GitHub·Render 비밀값에 직접 넣는다 |
| 시연 전 일시 정지 확인 | 시연 전날 | 7일 활동이 없으면 정지된다 |

## 4. 이 SQL이 하는 일

- **새 표 6개** (`sai_`): 시청과 열기 연결, 예측 모델 기록(열기마다 특징값·위험 점수·정답), 개입에 더한 칸(시각, 쇼츠/릴스, 고른 이유 번호, 위험도), 하루 요약(목표·본 시간·지킴), 시연용 비교 통계, 유형별 시작값.
- **새 함수 4개** (`sai_`): 표 버전 확인, 내 기록 지우기(우리 표 + 네 표), 다른 사용자 비교(계산 결과만, 한 칸 20명 미만이면 비움, 시연 모드면 시연 데이터), 처음 질문으로 유형 찾기.
- **권한:** 네 설계와 같다. 공개 키로는 자기 설치 번호로 넣기만 되고 읽기·표 만들기는 안 된다.
- **네 것을 쓰는 곳:** `usage_install_id()`(헤더의 설치 번호), `delete_own_usage()`(지우기에서 같이 부름). 바꾸지 않는다.

## 5. 확인한 것

이 PC에서 진짜 PostgreSQL로 시험했다 (`scripts/server/test_supabase_sql.py`):

1. 팀원 원래 `schema.sql`을 먼저 실행한 DB에 우리 SQL을 두 번 실행 → 오류 없음
2. 공개 키(anon)로 자기 기록 넣기 성공, 남의 설치 번호로 넣기·읽기·표 만들기는 거절
3. 앱이 실제로 만드는 기록 묶음(7개 표)을 JSON 그대로 넣기 성공
4. 비교 함수(시연), 유형 찾기, 지우기(우리 표 + 팀원 표) 동작
5. 되돌리기 SQL → `sai_` 표·함수만 지워지고 팀원 표·기록·함수는 그대로

진짜 Supabase는 이 시험 환경과 조금 다를 수 있다 (API 서버 PostgREST를 거친다). 팀원이 실행한 뒤 앱에서 실제로 올라가는지 한 번 더 확인한다.

## 6. 되돌리기 정리

| 문제 | 되돌리는 법 |
|---|---|
| Supabase에서 이상함 | `shortsai_v1_rollback.sql` 실행 → 우리가 더한 것만 지워짐. 앱은 6시간 안에 알아채고 팀원 표에만 올린다 |
| 앱 업로드가 이상함 | 앱 설정 → "사용 기록 보내기" 끄기 (그 즉시 안 보냄) |
| 앱 코드 자체를 되돌림 | git: `feature/risk-model` 브랜치(v0.11.1)로 돌아가 그 APK를 다시 설치. 서버 기능 작업은 `feature/server` 브랜치에만 있다 |
| 이미 보낸 기록을 지움 | 앱 설정 → "서버에 보낸 기록 지우기" (그 폰의 기록만) |
