브랜치 `feature/server`. 서버 코드는 저장소의 `server/` 폴더에 둔다. **확인받기 전에는 코드를 쓰지 않는다.**

## 0. 왜 직접 만드나

- 포트폴리오: REST API, DB 설계, 개인정보 설계, 테스트, 배포를 직접 보여 줄 수 있다.
- 기능: 다른 사용자와 비교하려면 여러 사람 기록을 모아 **계산한 결과만** 앱에 내줘야 한다. 원본 기록은 서버 밖으로 나가지 않는다.
- API 키 원칙 유지: 앱에는 서버 주소만 들어간다. DB 비밀번호는 서버 비밀값에만 둔다.
- 팀원 Supabase 설계(동의 창, 설치 번호, 대기열·재시도, 서버에서 지우기, 올리는 항목 기준)는 앱 쪽에서 이어받는다.

## 1. 구성

```
ShortsAI 앱 ──HTTPS(JSON)──▶ Spring Boot 서버 (Render 무료) ──▶ PostgreSQL (Neon 무료)
                                                                  ▲
GitHub Actions (주 1회, Python) ── 학습 결과(시작 모델·유형) 쓰기 ──┘
```

| 역할 | 도구 | 비고 |
|---|---|---|
| 서버 | Spring Boot 4.1.x, Java 21, Gradle | 만들 때 최신 안정판을 다시 확인 |
| DB | PostgreSQL (Neon 무료, 0.5GB) | 쉬면 잠들고 요청이 오면 저절로 깨어남 |
| DB 구조 관리 | Flyway | 표를 바꿀 때마다 순서대로 적용되는 SQL 파일 |
| 실행 | Render 무료 웹 서비스 (Docker) | 15분 쉬면 잠들고, 깨는 데 30초~1분. 메모리 512MB라 가볍게 설정 |
| 주 1회 학습 | GitHub Actions + Python (`scripts/risk-model` 재사용) | 서버가 잠들어도 상관없음 |
| 테스트 | JUnit + 내장 PostgreSQL (Docker 없이 실제 PostgreSQL로) | 이 PC에 Docker가 없다 |

서버가 잠드는 문제는 앱에서 푼다: 올리기는 대기열에 쌓았다가 실패하면 다시 보내고, 비교 통계·시작 모델은 하루 한 번 받아 폰에 저장해 둔다.

## 2. 개인정보 원칙 (바뀌는 것)

- **바뀜:** "기록은 기기 밖으로 보내지 않는다" → "**동의한 사람만, 정해진 항목만** 보낸다". 동의 전에는 아무것도 보내지 않는다. 설정에서 언제든 끌 수 있다.
- **그대로:** 화면의 글, 메시지, 비밀번호, 계정, 다른 앱 이름은 읽지도 보내지도 않는다. API 키는 앱에 넣지 않는다. 돈 드는 서비스는 쓰지 않는다.
- **사람을 알 수 없게:** 계정·이메일·전화번호 없음. 설치할 때 무작위 설치 번호와 비밀 토큰을 받는다.
- **지우기:** 앱의 "기록 초기화"나 동의 끄기에서 "서버 기록도 지우기"를 고르면 그 설치의 모든 줄을 지운다.
- **비교는 계산 결과만:** 한 칸(예: 밤 11시)에 사용자가 20명 미만이면 그 칸의 비교를 내주지 않는다.
- **시연 데이터:** 시연 모드에서만 더미 데이터로 계산한 비교를 내주고, 응답에 `demo: true`를 붙인다. 앱은 문구 옆에 "(시연 데이터)"를 붙인다. 실제 사용자에게 더미 숫자를 진짜처럼 보여 주지 않는다.

### 올리는 것 / 안 올리는 것

| 올림 | 안 올림 |
|---|---|

## 3. API (앱 ↔ 서버)

모든 요청은 JSON. 설치 등록 뒤에는 `Authorization: Bearer <토큰>` 헤더. 토큰은 서버에 해시로만 저장한다.

| 메서드·주소 | 하는 일 |
|---|---|
| `POST /api/v1/installs` | 설치 등록. 설치 번호와 토큰을 돌려준다 (동의한 뒤 한 번) |
| `DELETE /api/v1/installs/me` | 이 설치의 서버 기록을 모두 지운다 |
| `POST /api/v1/events` | 기록 묶음 올리기 (세션·열기·개입·잠금 시도·하루 요약). 같은 id는 다시 와도 한 번만 저장, 열기는 정답이 나중에 붙으면 고쳐 쓴다 |
| `GET /api/v1/stats/compare?demo=0\|1` | 비교 통계 (아래 5장). 하루 한 번 받는다 |
| `POST /api/v1/onboarding` | 처음 질문 답 → 비슷한 유형, 그 유형의 시작 모델, 추천 목표 |
| `GET /api/v1/models/latest?cluster=` | 최신 시작 모델 (새로 설치할 때) |
| `GET /actuator/health` | 서버 상태 (Render가 확인) |

남용 막기: 토큰마다 1분에 120번까지, 한 번에 올리는 줄 수·본문 크기 제한, 모든 값 범위 검사.

## 4. DB 표

| 표 | 내용 |
|---|---|
| `installs` | 설치 번호, 토큰 해시, 만든 때, 마지막 접속, 유형(cluster) |
| `sessions`, `opens`, `interventions`, `lock_attempts` | 위 "올림" 항목. 모두 `install_id`와 앱이 만든 `event_id`(기본키) |
| `daily_summaries` | 설치·날짜별 목표, 본 시간, 지킴 여부 |
| `models` | 주 1회 학습 결과: 버전, 유형, 가중치 JSON, 정확도, 쓰는 중 여부 |
| `clusters` | 유형별 중심값, 이름, 추천 목표 |
| `compare_stats` | 비교 통계 (매일 새벽 서버가 계산해 둠). 시연용은 `demo = true`인 줄 |

## 5. 다른 사용자와 비교 (사용자 확인: 시트 2번 자리 + 홈·리포트)

| 어디 | 무엇 | 예 (문구는 나중에 표로 확인) |
|---|---|---|
| 시트 "몇 분 볼래요?" 설명 자리 | 이 시간대에 쇼츠를 연 사람 중 3분을 고른 비율 / 시트에서 바로 나간 비율 | "지금 이 시간에 쇼츠를 연 사람 중 62%가 3분을 골랐어요." |
| 홈 "오늘 사용" 아래, 일일 리포트 | 목표가 비슷한 사람들의 지난주 목표 지킨 날 | "목표가 비슷한 사람들은 지난주 7일 중 평균 4일을 지켰어요. 나는 5일." |

- **좋은 행동 쪽 숫자만** (나감, 3분 고름, 지킴, 잠금). "평균 몇 분 봤다" 같은 숫자는 쓰지 않는다 — 많이 보는 사람이 "나도 괜찮네" 하는 역효과(부메랑 효과) 때문.
- 시트 설명 자리 우선순위: "남겨 둘까요?" > 비교 문구 > "오늘 남은 시간…" (남은 시간은 바로 위 게이지에도 나온다). 매번 나오지 않게 하루 몇 번만.
- 계산: 서버가 매일 새벽 지난 14일 기록으로 시간대(24칸)·목표 묶음(30분 이하, 31~45, 46~60, 60분 초과)별로 계산해 `compare_stats`에 둔다. 20명 미만 칸은 비운다.
- 시연 모드: 6단계 시뮬레이션의 가상 사용자 기록으로 같은 계산을 한 결과를 `demo = true`로 넣어 둔다.

## 6. 비슷한 성향 기본값 (처음 설치할 때)

1. 처음 질문 3개: 평소 하루에 쇼츠를 얼마나 보나요(30분 미만 / 30분~1시간 / 1~2시간 / 2시간 넘게), 주로 언제 보나요(아침 / 낮 / 저녁 / 밤), 하루 목표.
2. 서버가 가장 비슷한 유형을 고르고, 그 유형의 시작 모델과 추천 목표를 돌려준다.
3. 앱은 그 시작 모델로 시작하고, 그다음은 지금처럼 폰에서 배운다.

- 유형 묶기: 주 1회 학습 때 사람별 요약값(하루 평균 시청, 시간대 비율, 하루 연 횟수, 오래 본 비율)으로 k-means.
- 실제 사용자가 적을 때는 가상 사용자로 만든 유형·시작 모델을 쓴다. 이건 "다른 사용자 숫자"로 보여 주는 게 아니라 **시작값**이라 문제없다.

## 7. 주 1회 학습 (GitHub Actions)

- 매주 일요일 새벽 4시(한국 시간). Python이 DB에서 정답이 붙은 열기를 읽어 전체 모델과 유형별 모델을 학습한다.
- **안전장치:** 새 열기가 50개 미만이면 건너뛴다. 지난주 기록으로 시험해서 예전 모델보다 정확도(AUC)가 낮으면 바꾸지 않는다.
- 새 모델은 **새로 설치하는 사람의 시작값**에만 쓴다. 이미 쓰는 사람은 폰에서 배운 상태를 그대로 둔다.
- 학습용 DB 계정은 읽기 + 모델 표 쓰기만 되는 계정으로 따로 만든다.
