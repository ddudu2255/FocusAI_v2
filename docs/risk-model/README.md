# 예측 모델 (feature/risk-model)

목적: 지금의 위험 시간 규칙(`lib/ai.ts riskHours`, "밤 11시면 항상 짧게")을 **그 순간의 위험도 예측 + 밴딧 결정**으로 바꾼다. 계획 전체는 [HANDOFF.md](../HANDOFF.md)의 "다음 작업: 예측 모델".

진행 단계 (단계마다 확인받기):

1. 가상 사용자 성향 표 — **완료 (2026-10-26)**
2. 가상 데이터로 규칙 · 로지스틱 · 랜덤 포레스트 비교 — **완료 (2026-10-26), 계속 진행 판정**
3. 웹 — **완료 (2026-10-26)**, 아래 "3단계: 웹"
4. Java — **완료 (2026-10-26)**, 아래 "4단계: Java"
5. 새 문구 표 → 6. 시뮬레이션 비교 → 7. APK·폰 테스트 → 8. 커밋

되돌리기는 git으로만 한다 (`shortsai` 브랜치가 v0.10.1). 앱 안에 예전 규칙으로 돌아가는 스위치는 두지 않는다.

## 실행

Python 3.11 이상. 앱에는 들어가지 않고, 모델을 미리 학습·비교하는 데만 쓴다.

```bash
python -m pip install -r scripts/risk-model/requirements.txt
python scripts/risk-model/simulate.py   # out/data.npz (git에 넣지 않음)
python scripts/risk-model/compare.py    # out/results.md, out/results.json (시작 모델 가중치 포함)
```

같은 시드라 몇 번 돌려도 같은 결과가 나온다.

## 1. 가상 사용자 성향 (200명 × 12주)

**비율과 효과 크기는 추정치다.** 실제 데이터로 정한 값이 아니다. 패턴은 알려진 현상(취침 미루기, 확인 습관, 스트레스 대처 사용, 주말 증가, "어차피 망했으니" 효과)을 참고해 골랐고, 출처는 근거 문서 정리 때 확인한다.

**쇼츠를 많이 봐서 줄이고 싶은 사람**을 대상으로 한다 (2026-10-26 사용자 요청으로 바꿈. 하루 10~20분 보는 사람은 이 앱을 쓰지 않는다고 보고 뺐다).

| 유형 | 비율 | 하루 목표 | 앱 없이 하루 시청 | 하루 연 횟수 | 핵심 패턴 | 오래 봄 비율 |
|---|---|---|---|---|---|---|
| A 밤 몰아보기 | 25% | 45분 | 99분 | 약 14 | 밤 11시~새벽 1시에 길게 봄 | 10.5% |
| B 틈새 습관 | 20% | 40분 | 98분 | 약 30 | 자주 열고 짧게 닫음, 연쇄 열기 많음 | 3.5% |
| C 스트레스 반응 | 15% | 60분 | 136분 | 약 16 | 시간대보다 그날 기분(안 보임)이 큼 | 9.3% |
| D 주말 폭주 | 15% | 40분 | 91분 | 약 13 (주말 2배) | 주말 오후에 길게 | 9.6% |
| E 줄이려 애쓰는 | 15% | 30분 | 43분 | 약 9 | 약속 지킴 93%, 목표 넘으면 잘 잠금 | 3.2% |
| F 잠금 반동 | 10% | 40분 | 80분 | 약 14 | 잠금이 끝나고 30분 안에 길게 봄 | 7.8% |

- 사람마다 목표·횟수·위험 시간이 유형 평균 주변에서 다르다 (±20~30%, 위험 시간 ±1시간).
- 처음 3주는 앱이 새로워서 덜 본다.
- 모든 유형 공통: 목표 절반을 넘기면 더 무너짐, 닫자마자 다시 열면 위험, 직전에 길게 봤으면 위험, 어제 많이 봤으면 조금 위험, 최근 약속을 잘 지켰으면 덜 위험, 이유("스트레스 해소" ↑, "잠깐 보려고" ↓).
- **안 보이는 요인:** 그날 기분, 무작위 잡음. 모델이 완벽히 맞힐 수 없게 일부러 넣었다.
- 개입 효과(약속을 조이면 덜 보는지)는 이 데이터에 없다. 6단계에서 다룬다.

## 정답과 특징값

- **정답 "오래 봄"** = 한 번 열어서 그날 목표의 절반 이상 봄 (`goalMinutesOn`). 전체 9.3%.
- **특징값 10개** (그 순간 앱이 알 수 있는 것만):

| 특징값 | 로지스틱 입력 |
|---|---|
| 시각 | sin·cos (23시와 0시가 가깝게) |
| 주말 | 0/1 |
| 오늘 본 시간 ÷ 목표 | 최대 3 |
| 오늘 연 횟수 | log(1 + n) |
| 마지막으로 닫은 뒤 분 | log(1 + 분), 최대 12시간 |
| 직전 시청 길이 ÷ 목표 | 최대 3 |
| 잠금 끝난 뒤 분 | log(1 + 분), 최대 12시간 |
| 어제 이 시각까지 본 시간 ÷ 목표 | 최대 3 |
| 최근 7일 약속 지킨 비율 | 기록 없으면 0.75 |
| 이유 | 6개 중 5개를 0/1로 |

**HANDOFF와 다르게 한 것:** "최근 고른 이유"를 **이번에 고른 이유**로 썼다. 시트 순서가 방식 → 이유 → 약속이라, 약속 버튼을 보여 줄 때는 이번 이유를 이미 안다. 강함 단계처럼 이유를 묻지 않는 경우는 3단계에서 정한다.

## 2. 비교 결과 (가상 데이터)

전체 표: `scripts/risk-model/out/results.md`. AUC는 0.5가 동전 던지기, 1이 완벽.

| 평가 | 규칙 | 로지스틱 | 랜덤 포레스트 |
|---|---|---|---|
| 새 사용자 40명 (처음 설치한 사람) | 0.590 | 0.788 | 0.791 |
| 같은 사용자의 미래 (1~8주 → 9~12주) | 0.592 | 0.794 | 0.798 |

(많이 보는 사람으로 바꾼 뒤 다시 낸 값. 처음 값은 규칙 0.619, 로지스틱 0.837이었고 결론은 같다.)

- **멈춤 기준** (실행 전에 정함): 새 사용자에서 로지스틱 AUC가 규칙보다 0.05 이상 높지 않으면 멈춤. 결과 +0.198 → 계속 진행.
- **로지스틱 ≈ 랜덤 포레스트.** 정확도 차이가 거의 없다. 로지스틱은 폰에서 조금씩 다시 학습하기 쉽고, 왜 위험하다고 했는지 계수로 설명할 수 있다 → **로지스틱을 추천.**
- **유형별:** 모든 유형에서 로지스틱이 규칙보다 높다 (0.74~0.80). 규칙은 시간대만 보므로 B·D·E 유형에서 거의 동전 던지기(0.51)다.
- **폰에서 조금씩 학습:** 새 사용자가 시작 모델에서 출발해 기록마다 고치면 9~12주 AUC 0.790 → 0.805로 조금 오른다 (학습률 0.01). 학습률 0.05에서는 오히려 떨어졌다. 개선 폭이 작은 이유: 이 데이터에서 가장 큰 요인(오늘 본 비율, 약속 지킨 비율)이 모든 사람에게 공통이라 시작 모델이 이미 잘 맞힌다.
- **중요한 특징값:** 오늘 본 시간 ÷ 목표가 가장 크고, 다음이 직전 시청 길이, 최근 약속 지킨 비율, 오늘 연 횟수, 닫은 뒤 분.
  - 로지스틱의 "오늘 연 횟수" 계수가 음수(-0.57)다. 데이터를 만들 때는 양수 효과였지만, 많이 여는 B형이 짧게 보는 사람이라 사람 사이 차이가 섞였다. 모델이 틀린 건 아니지만 설명할 때 주의.

### 위험도 경계값

경계 40%·70%(HANDOFF 초안)는 오래 봄이 10% 안팎인 데이터에서 너무 높다. "높음"이 열기의 0.7%뿐이고, 오래 본 열기의 5%만 잡는다.

| 경계 | 높음에 드는 열기 | 그중 실제 오래 봄 | 오래 본 열기 중 높음이 잡은 비율 |
|---|---|---|---|
| 40% · 70% (초안) | 0.7% | 67.4% | 4.9% |
| 20% · 40% | 6.8% | 49.4% | 34.0% |

20%·40%면 "높음"이 열 번에 한 번 미만으로 드물게 나오고, 나왔을 때 두 번에 한 번은 실제로 오래 본다.

## 결정 (2026-10-26, 사용자 확인)

- **모델:** 로지스틱 회귀. 시작 가중치는 `out/results.json`의 `start_model`, 폰에서는 학습률 0.01로 조금씩 고친다.
- **위험도 경계:** 사람별 상대 기준 (아래 "6단계"). 처음 정한 20%·40%, 다음에 정한 10%·20%는 앱 안에서 거의 걸리지 않아 바꿨다.
- **원칙:** 막지 않고 번거롭게 해서 스스로 그만두게 한다. 엄격 모드는 지금 그대로 (연장·"3분만 더" 없음).
- **위험별 동작** (지금의 위험 시간 규칙을 대신한다):

| 위험도 | "몇 분 볼래요?" | 약속 끝 "조금 더 볼래요" | "3분만 더" 대기 |
|---|---|---|---|
| 낮음 | 평소대로 (3·5·10분, 연장할수록 10 → 5 → 3) | 평소대로 | 3초 |
| 보통 | 평소대로 + "3분 · 추천" 표시 | 평소대로 | 3초 |
| 높음 | **3분만** | 있음, 고를 수 있는 건 **3분만**, 횟수 제한 없음 | **10초** |

  - 지금 규칙과 다른 점: 시간대만 보지 않고 그 순간의 위험을 본다. 높음에서도 연장 횟수 제한(지금은 1번)이 없다.
- **밴딧:** 위험 보통·높음에서 위 동작을 그대로 쓸지, 한 단계 약하게 쓸지(높음 → 추천 표시만, 보통 → 표시 없음) 고른다. 효과가 없는 사람에게는 약하게 쓰도록 배운다. 개입 방식 밴딧은 그대로.
- **되돌리기:** git으로만. 앱 안에 예전 규칙 스위치는 두지 않는다.

## 한계

- 가상 데이터는 내가 정한 규칙을 따른다. 이 결과로 말할 수 있는 건 "이런 패턴이 있다면 모델이 찾아낸다"까지다. 사용이 줄었는지는 실사용으로만 말한다.
- 실제 숫자(세션 길이, 연 횟수)는 폰 기록으로 맞출 수 있다 (adb로 SQLite 복사). 아직 하지 않았다.

## 3단계: 웹 (TypeScript)

웹만 바꿨다. 서비스(Java)가 아직 점수를 내지 않으므로 폰 동작은 그대로다.

- `lib/risk-model.ts`: `compare.py`가 만드는 시작 모델 (200명 전체로 다시 학습). 손으로 고치지 않는다. `checks`는 날것 특징값 → 확률 예시로, TypeScript·Java가 같은 값을 내는지 테스트한다.
- `lib/risk.ts`: 특징값 변환, 점수, 위험도, 폰에서 학습(`learn`, 학습률 0.01), 최근 7일 약속 지킨 비율(`kept7`), 정답 채우기(`settleOpenLogs`).
  - 날것 특징값 순서는 `RAW_FEATURES`. 이유를 모르면 `-1`(이유 칸을 평균으로 둔다 = 표준화하면 0).
  - 정답 = 그 열기에서 본 시간 합 ≥ 그날 목표(`goalMinutesOn`)의 절반. 4단계에서 고침: 아래 "정답 규칙".
  - 고친 가중치는 settings 표의 `riskModel`에 둔다. 기록 초기화하면 시작 모델로 돌아간다.
- 새 표 `open_logs`(열기마다 특징값·점수·위험도·정답), `app_events`(개입 스위치 끄기/켜기, 측정만). 개입 기록에 `open_id`, `risk_score`, `risk_band`, `tighten`, `tighten_followed` 칸을 더했다. 표·칸은 더하기만 했다.
- 정책표(`lib/policy.ts`): `ai.model`(가중치·표준화 값·경계·kept7), `ai.tighten`(full/soft 밴딧), `ai.risk`는 위험 높음의 동작(약속 최대 3분, "3분만 더" 대기 10초, 연장 횟수 제한 없음). 정책 버전 `ai-3`.
  - `riskHours`는 위험 시간 10분 전 알림과 "남겨 둘까요?" 추천에만 남는다 (사용자 확인).
- 밴딧(`lib/ai.ts tightenTable`): 칸 "medium"·"high", 선택 full·soft, 사전분포 full Beta(2, 1) · soft Beta(1, 1).
- 테스트: `lib/risk.test.ts` (16개). 전체 웹 테스트 87개 통과.

**4단계(Java)에서 할 일:** 열 때마다 날것 특징값을 재고(오늘 연 횟수, 닫은 뒤 분, 직전 시청, 잠금 끝난 뒤 분 등) 점수를 내서 `openLogs`로 보낸다. 위험도와 밴딧 선택으로 "몇 분 볼래요?" 칩·연장·"3분만 더" 대기를 바꾼다. 위험 시간 규칙의 제한(`isRiskHour`)과 위험 시간 한 줄(A7)은 뺀다.

## 4단계: Java

- `GuardRisk.java`: 특징값 재기(`features`), 변환·점수·위험도(lib/risk.ts와 같은 계산), 위험도별 동작(`action`).
- 열기 = 쇼츠·릴스를 열어 개입 시트가 뜬 순간 (`ShortsGuardService.decide`). 개입이 꺼져 시트가 없으면 열기가 아니다.
  - 시트가 뜰 때 이유 없이(-1) 점수를 내고, 이유를 고르면 이유를 넣어 다시 낸다. 약속 끝·강함 시트는 같은 열기의 점수를 쓴다.
  - 열기 기록은 그 열기의 첫 시트 기록과 함께 한 번 보낸다 (`GuardState.addOpen`, `openLogs`).
  - 오늘 연 횟수는 시트가 뜬 횟수 (`bumpToday("open")`), 닫은 뒤 분·직전 시청 길이는 마지막 시청 기록에서, 잠금 끝난 뒤 분은 `blockedUntil`에서 (잠금 중이면 기록 없음).
- 위험도별 동작 (`GuardFlow`): 높음 full = 약속 칩 3분만, "조금 더 볼래요"는 그대로(역시 3분만), "3분만 더" 10초. 보통 full·높음 soft = "3분 · 추천" 칩. 보통 soft·낮음 = 그대로.
  - full/soft는 위험도마다 하루 한 번 뽑아 그날 내내 쓴다 (`GuardState.todayChoice`).
  - 예전 위험 시간 제한(`isRiskHour`: 3분, 연장 1번, 10초)과 시트 위 위험 시간 한 줄(A7)은 뺐다. 새 문구는 5단계.
  - "남겨 둘까요?"(A5)는 그대로. 위험 보통 추천과 겹치면 칩 하나, 설명은 A5 문장.
- 시청 기록에 `openId`를 붙인다 (`GuardState.startSession`). 연장, 10분 안 이어 보기, PIP 다시 묻기도 같은 열기다.
- 테스트: `GuardRiskTest` 8개 (점수는 lib/risk-model.ts의 checks를 그대로 읽어 Python·TypeScript와 맞춘다). Java 42개, 웹 88개 통과.

### 정답 규칙 (4단계에서 고침)

시청 기록은 "보기"를 고른 뒤에야 생겨서, 시트에서 바로 나가면 시청 기록이 없다. 그래서 열기와 시청을 `openId`로 묶는다 (`lib/risk.ts settleOpenLogs`).

- 이 열기에서 본 시간 합 ≥ 그날 목표의 절반 → **오래 봄** (바로 정함).
- 아니면 열기가 끝났을 때 **오래 안 봄**: 다음 열기가 생겼거나, 지금 보고 있지 않고 마지막 시청(없으면 연 시각)에서 30분이 지났을 때.

## 5단계: 문구 (2026-10-26 사용자 확인)

시트 맨 위 한 줄(작은 창 안내와 같은 자리). "몇 분 볼래요?" 단계에서 띄운다 (`GuardCopy.riskNotice`).
점수를 가장 많이 올린 요인으로 앞부분을 고른다 (`GuardRisk.topReason`, 0.3 미만이면 "그 밖").

| 요인 | R1: 3분만 (높음 full) | R2: 추천만 (보통 full · 높음 soft) |
|---|---|---|
| 오늘 이미 많이 봄 | AI · 오늘 이미 꽤 봐서 길어지기 쉬워요. 3분씩 끊어서 볼게요 | AI · 오늘 이미 꽤 봐서 길어지기 쉬워요. 짧게 3분은 어때요? |
| 닫자마자 다시 엶 | AI · 방금 닫았다가 다시 열었어요. 3분씩 끊어서 볼게요 | AI · 방금 닫았다가 다시 열었어요. 짧게 3분은 어때요? |
| 직전에 길게 봄 | AI · 방금 길게 봤어요. 이번엔 3분씩 끊어서 볼게요 | AI · 방금 길게 봤어요. 짧게 3분은 어때요? |
| 시간대·주말·어제 이 시각 | AI · 평소 길게 보던 때예요. 3분씩 끊어서 볼게요 | AI · 평소 길게 보던 때예요. 짧게 3분은 어때요? |
| 그 밖 | AI · 지금은 길어지기 쉬운 때라 3분씩 끊어서 볼게요 | AI · 지금은 길어지기 쉬워요. 짧게 3분은 어때요? |

- 연장("몇 분만 더 볼래요?")에서도 같은 한 줄을 다시 보여 준다 (R3). 제목·설명은 그대로.
- "남겨 둘까요?"(A5)가 나오면 이 줄은 띄우지 않는다. 작은 창 안내가 우선.
- R4 (설정 → AI 패널 "AI가 지금까지 배운 것"): "길어지기 쉬운 때: 쇼츠를 연 {N}번의 기록을 보고 배우는 중이에요". N은 폰에서 배운 횟수(`riskModel.updates`). 0이면 "길어지기 쉬운 때: 처음엔 기본값으로 시작해서, 쓰는 만큼 배워요".
- AI 개인화 설명 (설정 → AI 패널, 사용자 확인): "내 기록을 보고, 나에게 잘 맞는 개입 방식과 문구를 고르고, 길어지기 쉬운 순간에는 3분씩 끊어 보게 하고, 평소 오래 보는 시간 전에는 미리 알려 줍니다. 계산은 모두 이 폰 안에서 하고, 기록은 밖으로 보내지 않습니다. 끄면 정해진 규칙대로 번갈아 보여 줍니다."

### 학습에서 빼는 열기 (사용자 확인)

3분 제한이 걸린 열기(위험 높음 + full)는 정답만 채우고 모델을 고치지 않는다 (`lib/risk.ts wasLimited`). 제한 덕분에 멈춘 것을 배우면 모델이 그 순간을 덜 위험하게 보고 제한을 풀어, 다시 오래 보는 순환이 생긴다. 모델은 "그냥 두면 오래 볼까"만, 제한의 효과는 밴딧이 잰다. 추천만 붙은 열기는 막지 않으므로 배운다. 열기 기록에 `tighten`을 함께 남긴다.

"평소 오래 보는 시간"(알림, "남겨 둘까요?")은 실제로 본 시간으로 정하므로, 그 시간에 덜 보게 되면 바뀐다. 그대로 둔다.

## 6단계: 개입 시뮬레이션 (2026-10-26)

`scripts/risk-model/policy_sim.py`. 같은 가상 사용자에게 개입을 걸어 비교한다. 개입에 대한 반응(약속이 끝날 때 그만둘 확률, 추천을 따를 확률, 연장이 막혀 나간 뒤 다시 열 확률)은 **추정**이다 (`RESPONSE`). 그래서 이 결과로 하루 시청이 얼마나 줄었는지는 말할 수 없고, 설계대로 움직이는지(얼마나 자주 걸리는지, 학습이 꼬이지 않는지)만 본다.

| 경우 | 하루 시청 | 일주일 3분 제한 | 일주일 추천 표시 |
|---|---|---|---|
| ① 개입 없음 | 100.7분 | 0 | 0 |
| ⑤ 약속만 (위험도 개입 없음) | 62.8분 | 0 | 0 |
| ② 지금 앱 (위험 시간대 3분, 연장 1번) | 60.8분 | 29.2 | 0 |
| ③ 새 방식, 고정 10%·20% | 63.2분 | 0.1 | 1.2 |
| **③ 새 방식, 사람별 상대 기준 (채택)** | 63.5분 | 3.7 | 9.2 |

- **고정 확률 기준이 걸리지 않는 이유:** 앱의 약속 때문에 한 번에 오래 보는 일이 크게 준다(하루 1.33번 → 0.31번). 폰 학습이 이를 정직하게 배워 확률이 낮아지므로, 고정 선은 어떤 값이든 시간이 지나면 거의 넘지 않는다 (10%·20%에서 높음 비율 1주 0.6% → 12주 0.1%).
- **사람별 상대 기준 (`lib/risk.ts bandsFor`):** 그 사람의 최근 14일 열기 점수 중 상위 15%면 보통, 상위 5%면 높음. 단 확률 2%·4% 미만이면 걸지 않는다 (그 사람의 평범한 순간이 4% 안팎). 열기가 50번 쌓이기 전(많이 보는 사람은 3~4일)에는 고정 10%·20%. 12주 동안 높음 비율이 4~5%로 유지된다. 웹이 정책표의 `model.bands`로 넘기고, 서비스는 그대로 쓴다.
- **유형별 3분 제한 (일주일):** 틈새 습관 5.1, 스트레스 4.4, 밤 몰아보기 3.8, 주말 3.1, 잠금 반동 2.8, 줄이려 애쓰는 2.1. 지금 앱은 같은 사람들에게 4.7~39.6번.
- **하루 시청이 비슷한 이유:** 3분씩 끊을 때 더 그만두는 정도를 추정으로 약하게 잡았기 때문이다. "AI가 더 줄이지 못한다"는 뜻이 아니다. 이 질문은 실사용(AI 켜기/끄기 비교)으로만 답할 수 있다.
- **학습 수정(3분 제한 열기는 배우지 않음):** 이 데이터에서는 ③과 ④의 차이가 작다.
- **밴딧:** 12주 뒤에도 모든 유형에서 full(정한 대로)이 조금 낫다고 본다. 높음이 드물어 배울 기록이 적고, 사전분포가 full 쪽이다.
- **실험: "잠깐 보려고"만 누르고 오래 보는 사람** (기준 10%·20%, 밤 몰아보기 50명): 처음 2주는 덜 걸리지만(1.0% vs 정직한 사람 2.6%), 3주째 따라잡고 12주엔 더 자주 걸린다(9.6% vs 4.5%). 이유는 모델에 그대로 둔다 (사용자 확인).

### 목표를 지키는 중이면 한 단계 약하게 (2026-10-26 사용자 확인)

목표를 꾸준히 지키는 사람에게 3분씩 끊기는 귀찮기만 하다. 상대 기준은 그런 사람에게도 "가장 위험한 5%"를 찾아 걸기 때문에, 따로 막는다.

- **조건:** 최근 7일(오늘 제외) 하루도 빠짐없이 그날 목표 안에서 끝냄 (`lib/risk.ts keepingGoal`, 나무의 "지킨 날"과 같은 기준). 기록이 처음 생긴 지 7일이 안 됐으면 원래대로.
- **동작:** 높음 → "3분 · 추천"만, 보통 → 없음 (`GuardRisk.action`의 keeping). 하루라도 목표를 넘기면 다음 날부터 원래대로.
- 이때는 밴딧 선택을 무시하므로 밴딧 학습에도, 모델 학습 제외(`wasLimited`)에도 넣지 않는다. 열기 기록에 `keeping`을 남긴다.
- 시뮬레이션: 목표 60분 안에서 주로 보는 사람(지킨 날 약 90%)은 추천 표시가 일주일 4.3번 → 2.9번으로 준다. 많이 보는 6개 유형은 7일 연속으로 지키는 일이 드물어 거의 그대로다.
